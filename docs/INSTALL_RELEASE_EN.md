# Installation, Upgrade and Release Checks (1.3.0)

[中文](INSTALL_RELEASE.md) | [English](INSTALL_RELEASE_EN.md)

The default is bundled downloading in one product container; advanced existing mode connects existing downloaders. Phone SSH installation still requires a Linux NAS, SSH, Docker Compose and Docker permissions for the account. Verify the SHA256 host fingerprint first. Current validation focuses on x86_64 Linux; ARM has not been tested, and universal NAS compatibility is not promised.

Extract the installation package and run `sh install.sh --dir /your-data-disk/docker/nas-download --port 7120 --mode bundled` in a private temporary directory. Use `--downloads /your-data-disk/downloads` to specify the directory. The service port range is 1024–65534; in bundled mode, the next port is used for BT TCP/UDP, and the internal download management port is not exposed. existing mode does not automatically move existing tasks.

A complete installation package contains `nas-download-image.tar.gz` at its root. The installer imports it with Docker load, without building on the NAS. The lightweight source package has no image; the first build must be able to obtain base images and dependencies. Generate a complete package with `python deploy/package.py --image /path/to/nas-download-image.tar.gz`; without arguments, a lightweight package is generated. Android bundles the same installation package; rebuild the APK after freezing the image and service code.

The phone uploads to the private /tmp directory created for that installation and shows the actual upload percentage. Time is allowed for large-package uploads and image import. Success cleans up only that private staging directory; failure retains staging files for troubleshooting. The successful installation protocol includes NAS_DOWNLOAD_READY, NAS_DOWNLOAD_SETUP_CODE and NAS_DOWNLOAD_PROJECT. Keep the setup code private. A reachable web page does not mean a download has completed; installation in bundled mode must also verify engine health.

Directory write access is checked for the current account. The service uses the specified UID/GID and does not recursively change permissions on other directories. Upgrades reuse the same directory and project, preserving credentials, keys, download paths and tasks. Before switching, back up the matching database, engine recovery files and deployment configuration. On failure, stop the corresponding instance before restoring its matching snapshot; never overwrite new records in a running database with an old database. Download files are stored separately; removing the program retains files by default.

Release checks: backend, Android, image and bundled installer must all be 1.3.0, with Android code 6. Keep the existing release signing identity. Check packages for private addresses, accounts, tokens, databases and keys, and retain third-party materials. Record each artifact's SHA256, signature, actual test environment and unverified items. The public summary is in the [acceptance record](ACCEPTANCE_1_3_EN.md); source tests do not establish successful phone SSH installation or compatibility with all devices.

This version was tested in an isolated x86_64 Linux NAS environment for actual single-container downloads, pause/resume, deletion and replacement, engine failure recovery, restart and forced rollback. Normal two-container migration was verified: the old engine stopped, and original sessions, task hashes, paths and file SHA256 values were preserved. See the final acceptance report for specific evidence. The complete package includes a built image. The public release is a beta; long-term operation has not been observed, and compatibility with all NAS devices, ARM or all phones is not claimed. The phone SSH protocol and signed upgrade were checked separately using an isolated emulator.
